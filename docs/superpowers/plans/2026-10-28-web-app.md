# Kindway web app (Phase 6B) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Kindway as an installable, offline-capable web app on Cloudflare Pages that the owner's friend uses daily from an iPhone Home Screen.

**Architecture:** The existing Expo Router web export (`web.output: "single"`) gets a PWA shell (customised `public/index.html`, manifest, icons) and a Workbox `generateSW` service worker that precaches only the app's own files. The four Edge Functions get a shared CORS wrapper driven by an `ALLOWED_ORIGINS` secret. All web-specific behaviour is decided through one module, `src/services/platform.ts`, so tests switch it with `jest.mock`.

**Tech Stack:** Expo SDK 58, Expo Router, react-native-web, Supabase (Auth PKCE, Edge Functions on Deno), workbox-cli, Cloudflare Pages (GitHub integration).

**Spec:** `docs/superpowers/specs/2026-10-28-web-app-design.md` (approved by the owner on 2026-10-28)

## Global Constraints

- `expo` is `~58.0.19`; read `https://docs.expo.dev/versions/v58.0.0/` before touching an Expo API. Add packages only with `npx expo install` (dev deps: `npx expo install <pkg> -- --save-dev`).
- Done means all of these pass: `npx expo lint`, `npx tsc --noEmit`, `npx jest`, plus `npm run build:web` from Task 4 on.
- Only `EXPO_PUBLIC_SUPABASE_URL` and `EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY` may end up in the web bundle. `EXPO_PUBLIC_AUTH_LINK_URL` is ignored on the web.
- Every "is this the web?" check goes through `onWeb()` from `@/services/platform`, read when called, never at module load.
- No text that can be reached on the web says "Android". Screens that are Android-only (reminders, widget) keep their current wording.
- The service worker never caches Supabase or Edge Function responses, only the files in `dist/`.
- Copy uses the app's typography: ’ “ ” …, sentence case, no exclamation marks.
- Commits: the owner pushes, and Cloudflare publishes `main`. Commit only once the owner has OK'd committing. The Phase 6 changes still uncommitted in the tree go in their own commit first.

## Review Focus

1. **A deploy while the app is open.** `asyncRoutes.web` loads route chunks lazily, so a page still running the old version asks for old chunk names. These must still load from the old precache, so a waiting worker must not take over by itself (no `skipWaiting`). Pinned in Task 4.
2. **A signup started in the Home Screen app, with the confirmation link opened in Safari.** The person should see "Email confirmed", not an error. Pinned in Task 3.
3. **A password reset requested in the Home Screen app, with the link opened in Safari.** It can't be finished there, because PKCE ties the code to the storage that asked for it. The page should explain this and let them request the link again from Safari, where it will work. This corrects the spec's "a reset completes in Safari", which holds only when the reset was requested from Safari. Pinned in Task 3.
4. **Requests with no `Origin` header (the Android app) or from an origin that isn't allowed.** Android behaves exactly as before. An origin that isn't allowed gets no `Access-Control-Allow-Origin`. Error responses (401, 429…) to allowed origins still carry CORS headers, so the app can read them. Pinned in Task 1.
5. **Opening `/entry/<id>` or `/auth/confirm?code=…` with no signal.** Navigations fall back to the cached `index.html`. Pinned in Task 4.
